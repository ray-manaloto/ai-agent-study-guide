Event Loop Steps

1
Poll Events
The main loop uses tokio::select! to poll both terminal (crossterm) events and codex events concurrently.
Active
Source Code

Handle Keyboard Input
Key events are routed to ChatComposer for text input, or handled as shortcuts (Ctrl+C interrupt, Enter submit, etc.).

User Response
The user's decision sent back to the agent via Op::ExecApproval or Op::ApplyPatchApproval.

  • Denied → Skip this action
  • ApprovedWithAmendment → Approve + update policy

Thread State Machine

stateDiagram-v2 [*] --> Idle: App created Idle --> Initializing: start_thread Initializing --> Ready: SessionConfigured Ready --> ProcessingTurn: UserTurn submitted ProcessingTurn --> WaitingApproval: ApprovalRequest ProcessingTurn --> Ready: TurnComplete WaitingApproval --> ProcessingTurn: Approval sent Ready --> Resuming: resume_thread Resuming --> Ready: SessionConfigured Ready --> [*]: Exit

State Descriptions

Idle
Initial state before any thread is started. App is created but not connected to an agent.
Initializing
ThreadManager is creating a new CodexThread. Waiting for SessionConfigured event.
Ready
Thread is ready to accept user input. Waiting for user to type and submit a message.
ProcessingTurn
Agent is processing the user's turn. LLM calls, tool execution in progress.
WaitingApproval
Agent needs permission. ApprovalOverlay is shown, waiting for user decision.
Resuming
Loading a saved session from rollout file. Restoring conversation history.
